## 体积的来源

仓库只有 README（1,572 字节）和 HTML（1,423,569 字节）。HTML 内嵌 Three.js 与游戏代码，未携带 Godot/WebAssembly 运行时；字体通过 Google Fonts 加载。

本地 gzip level 9 压缩 HTML 为 443,425 字节；在线服务器本次响应的 gzip Content-Length 为 448,328 字节。字体不含在这两个数字中。

模型通过几何生成代码创建。纹理在 GPU 渲染到纹理，生成反照率、ORM 与法线贴图，并按纹理集缓存。音频通过 WebAudio 合成与缓存。项目采用单张港口关卡、三处中继目标、两类敌人的集中内容范围。

## 画面的主要来源

PBR 材质中的法线、粗糙度、金属度、积水与污渍；一致的冷暖照明；柔阴影、雾和轮廓层次；地面平面反射；环境探针；低强度辉光、自动曝光、调色和颗粒。纹理细节与光照表达承担大量质感，不需要每个铆钉、划痕都做独立模型或专属大图。

## 本次实测及边界

使用系统 Chrome headless、RTX 4060 Ti / ANGLE D3D11、1280×720、干净浏览器上下文、本地 HTTP 服务，运行源码自带 `?bench=1` 摄像机巡航。该模式主动关闭音频；没有实测手机、音频输出或完整激烈战斗。

- 本次进入 ready：34.22 秒。启动日志 level 阶段约 18.86 秒。
- 约 36 秒巡航：平均帧间隔 16.7ms，P99 17.9ms，约 60 FPS。
- high 档，内部渲染 1280×720，动态缩放系数 1；该样本没有靠降分辨率达到结果。
- 相邻统计快照约 361–455 draw calls、202–287 万三角形（计入多渲染通道），不能当作唯一场景三角形数。
- 材质统计：24 套生成纹理，估算 111.6 MiB；贴花估算 55.9 MiB，合计 167.5 MiB。这是项目自己的纹理容量估算，不是实测进程内存，也不含全部渲染目标。
- 游戏错误计数 0；控制台有着色器导数警告与本地 favicon 404。

小包体成立；运行帧时间在上述范围成立；首次启动依然有显著生成/编译成本。不能据此断言红米 K40 稳定 60 FPS。

## 对潜渊少女的适用结论

优先借鉴预算、缓存和生成时机：共享材质/贴图、在加载阶段完成资源生成与着色器预热、减少运行时材质变体、限制每帧提交与实体数量、独立 Web 画质和动态分辨率。

现有 Godot 项目也有程序化几何和合批；问题不是缺少程序生成，而是浏览器主线程同时承担大量生成与冷编译。应把可缓存内容移到构建阶段或一次性预热，保留必要的低成本运行时变化。

包体优先处理 Boss 贴图、音频与重复资源；人物立绘/配音/多区域内容有独立价值，不能直接套用单关卡样例的 1.4MB 指标。Godot Web 运行时本身也构成固定成本，仅换成程序生成不会消失。

本次参考分析不代表此前 Web 修复已完成发布：静态立绘、去重、音频总线与渲染/分片加载的改动仍需完成最终导出与回归。

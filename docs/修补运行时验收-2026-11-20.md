# 修补运行时验收

本轮将已定位的 Godot 4.7.2 反射探针 cubemap 泄漏修复编译并运行，保留原版 Godot 作为对照。游戏没有关闭反射效果或降低探针分辨率。

## 构建与复现

官方源码 `4.7.2-stable`，源码包与发布 SHA-256 对上；LLVM-MinGW 20261117 UCRT x86_64、SCons 4.11.1。补丁仅修改 `_reflection_atlas_clear`，释放此前遗漏的 `color_buffer`，由 RenderingDevice 的依赖清理释放六个切片视图。

- 补丁：`tools/engine/godot-4.7.2-reflection-cleanup.patch`
- 构建：`tools/engine/build_runtime.ps1`
- 打包运行时：`build/runtime-patched/template_debug/godot.exe`
- 源码调试运行时：`build/runtime-patched/template_debug-source/godot.exe`
- 冻结测试项目：`D:/123/tmp/godot472-reflection-fix/projects/soak_source_enginefix`

构建为 `template_debug`，保留断言和脚本错误检查；这不是最终 Release 构建。D3D12、ANGLE、WinRT 依赖没有安装，当前构建针对 Vulkan 验证，不覆盖上述后端。官方编辑器仍用于资源导入及 PCK 导出。

## 帧时间

海湾区同进程两轮各五分钟完成。配置：i5-12400F / RTX 4060 Ti、1920×1080、Forward+、quality=1、2× MSAA、渲染倍率 1.0、关闭 VSync，两名队友、队列增援、持续射击、三轮动态事件。

| 轮次 | 平均 FPS | P95 ≤ | P99 ≤ | 最大帧 | >33.3 / >45 / >100 ms | 射击 | 事件落点 |
|---|---:|---:|---:|---:|---:|---:|---:|
| 第一次 | 133.55 | 10.2 ms | 12.9 ms | 56.387 ms | 1 / 1 / 0 | 4,501 | 3 |
| 第二次 | 133.94 | 10.2 ms | 12.9 ms | 19.654 ms | 0 / 0 / 0 | 4,500 | 3 |

分位数为 0.1 ms 直方图上界。第一次约 16.39 秒出现 56.387 ms 帧，同时记录 draw/specialization 各增加 4；这只是同帧相关，不是已证实的全部耗时归因。加载至可操作为 25.707 / 14.868 秒。

`review/soak_bayport_enginefix_manifest.json`：正常退出、完整结果、源码无变化、无并发、无运行错误。进程日志中系统 CPU 最高 37.4%，没有超过 85% 的主机负载样本。全过程退出无 Texture RID 警告。

两次返回机库均为 1,288 节点、0 孤儿、0 粒子池键；静态内存 344.956 / 345.913 MiB，差 0.957 MiB。缓存网格增加 169 个、粒子资源增加 14 项；显存增加约 14.33 MiB，属于不同战斗演化后的总观察值，不能等同于同一机库空循环的纹理泄漏，也不能据两个周期保证所有缓存无限长时间不增长。总表 `review/enginefix_performance_summary.json` 保留原始状态。

监控记录可执行文件哈希、源码前后哈希、游戏树内存、系统和游戏进程 CPU；可选 `--host-profile` 在主机 CPU 超过 85% 时记录主要外部进程。它只用于解释主机干扰，不暂停其他应用、不选择性删除慢帧。源代码调试运行时的编译选项与官方编辑器不同，不将 FPS 差异全部解释为补丁收益。

## 使用

项目根目录的 `启动游戏.bat` 优先使用修补源码运行时，若本地构建缺失则回退官方引擎。`tools/perf_monitor.py` 同样优先采用修补版，仍可通过 `--engine` 显式选择。

本地冻结测试包位于 `build/perf-candidate-20261120/`，`Play.bat` 启动；`candidate.json` 记录 EXE/PCK 哈希。它包含诊断测试，是用于复核的 Debug 候选包，没有对外发布，也不替代正式 Release、低配或移动端验收。

整理后的 `AbyssDiverGirls.exe` 已实际启动同目录 PCK 并通过机库及设置截图检查，无错误和退出泄漏警告；日志 `review/enginefix_candidate_start.log`。最终源码/可执行文件/包指纹及验证索引汇总于 `review/enginefix_final_evidence.json`。首轮仍有一次 56.387 ms 慢帧，当前结论是已修复已复现的资源泄漏且本机两轮表现稳定，不是所有设备和所有地图的零卡顿保证。

# 数值体系（当前实现）

> 本文档对应 2026-11 的代码状态，列出机甲、武器、敌人、背部模块、经济与成长的数值计算方式，并在末尾给出已发现的异常点。
> 审计工具：`godot --headless --path . -- --balance_audit` → `review/balance_audit.json`。

## 0. 数据来源

| 数据 | 文件 | 合并方式 |
|---|---|---|
| 模块（躯干/底盘/手臂/背部/动力炉） | `data/ext/equipment.gd`、`data/ext/cores_gens_pack.gd` | `GameData.MODULES` |
| 物品/消耗品 | 同上 + `progression.gd` | `GameData.ITEMS` |
| 弹匣与射击资源 | `scripts/game_data.gd` 的 `AMMO` | 按武器类型共享 |
| 敌人 | `scripts/bug.gd` 的 `KINDS` + `data/ext/enemies.gd` | `GameData.ENEMIES` |
| 掉落表 | `game_data.gd` 的 `LOOT_TABLES` + `EXTEND` | `GameData.LOOT_TABLES` |
| 成长 | `data/ext/progression.gd` | `FACILITIES / RESEARCH / PILOTS / CREW / ABILITIES` |
| 世界观/剧情 | `data/story/*.json` | 只影响文案，不参与战斗数值 |

模块的 6 个槽位：`core / legs / arm_l / arm_r / back / gen`。每个模块同时提供外观与数值；建模脚本按 `scripts/modules/<id>.gd` 约定加载。

## 1. 机甲数值

### 1.1 模块字段

| 槽位 | 关键字段 | 说明 |
|---|---|---|
| 躯干 core | `hp / cargo / armor / armor_class / drain / ergo / recon / w / v / rar` | 结构、货舱、减伤、防弹等级、待机耗能 |
| 底盘 legs | `speed / load / armor / armor_class / drain / type / ergo` | 移动速度、承重、减伤、行走方式 |
| 手臂 arm | `weapon / dmg / rate / pen / spread / range / reach_m / mag(类型) / cost(激光/近战)` | 武器 |
| 背部 back | `cargo` 或 `ability / cd / cost / dmg / count / dur` | 货舱或主动技能 |
| 动力炉 gen | `energy / eff` | 能源上限、耗能倍率（eff 越低越省电） |

### 1.2 整机汇总 `GameData.compute_stats(loadout)`

```
hp          = Σ 模块.hp                 （实际只有躯干提供）
cargo       = Σ 模块.cargo
energy      = Σ 模块.energy             （实际只有动力炉提供）
drain       = (Σ 模块.drain + 0.04) × gen.eff
mass        = Σ 模块.w
speed       = 底盘.speed
load        = 底盘.load
armor       = Σ 模块.armor
armor_class = max(躯干.armor_class, 底盘.armor_class)
weapon_range= max(左臂.range, 右臂.range)，没有武器时为 10
recon       = Σ 模块.recon
view_range  = max(10, weapon_range) + recon
ergo        = clamp(参与模块的 ergo 平均值 − max(0, 背部件重量 − 4) × 1.2, 15, 95)
```

之后由 `Growth.stat_hook` 叠加设施、研究、驾驶员、船员、熟练度、餐点加成（加算，不乘算）。

### 1.3 质量、超载与速度

```
总质量 = Σ 模块.w + 货物重量
超载   = max(0, 总质量 − 底盘.load)
速度倍率 = clamp(1 − 超载 / 底盘.load × 1.5, 0.40, 1.0)
```

- 精英专精「负重肌力」把系数从 1.5 降到 1.05。
- 超载 ≥ 40% 时直接触底 40%，不会归零。
- 底盘 `overload_immune`（泰坦/巨像等）直接忽略超载。
- 实际速度 = `speed × speed_mult()`，还会被以下因素乘算：应急模式 ×0.45、底盘损毁 ×0.55、底盘完好度 <50% 线性 0.78~1.0。

### 1.4 能源

```
待机耗能 = stats.drain × drain_mul × 1.6（移动时） × gen_pen
gen_pen  = 1.5（动力炉损毁） / 1.25~1.0（动力炉完好度 <50%） / 1.0
```

- `stats.drain` =（所有模块 drain 之和 + 0.04 维生） × 动力炉 eff。
- 冲刺、技能、激光/近战开火、护盾额外扣能源；实弹武器不耗能。
- 能源归零 → 应急模式 15 秒：速度 ×0.45、所有武器停火；燃料电池可恢复，否则机甲瘫痪。
- HUD 剩余秒数使用 `_last_drain`（含移动/漏电），但不含开火消耗。

### 1.5 人机工效、散布与换弹

```
ergo_factor = clamp(0.75 + (ergo − 30) / 140, 0.72, 1.22)
实际散布    = 面板 spread × (1 + 手臂损伤惩罚) × 瞄准倍率
手臂损伤惩罚 = clamp((0.5 − 手臂完好度)/0.5, 0, 1) × 0.45
瞄准倍率    = 1.0（不瞄） / 0.65（瞄准） / 0.45（狙击开镜）
换弹时间    = 类型 reload / ergo_factor × (1 + 手臂损伤惩罚) × 精英专精 0.85
```

- 面板 `spread` 是角度值，但 `try_fire` 实际取 `randf_range(−spread, spread) × 0.5`，即有效半角约为面板值的一半。
- 持续射击没有精度累积（无 bloom）；后坐力只影响视觉，不改变弹道。

### 1.6 玩家承伤与护甲

```
ac_bonus = max(0, armor_class − 2) × 0.03
armor    = clamp(stats.armor + ac_bonus, 0.0, 0.65)
实际伤害 = 来袭伤害 × (1 − armor)
```

- 护盾激活期间完全免疫伤害。
- `armor_class` 只提供每级 3% 的额外减伤，不参与“穿甲对抗”。
- 部位完好度会下降，但总 HP 独立；部位归零只关闭对应功能（武器/移动/技能）。

## 2. 武器数值

### 2.1 类型与射击资源

| 类型 | 射击资源 | 弹匣 / 换弹 | 代表 |
|---|---|---|---|
| mg 机枪 | 弹药 | 36 / 1.8s | 12.7mm 转管、14.5mm 重机枪 |
| autocannon 自动炮 | 弹药 | 36 / 1.8s | 20~40mm 机炮、近防炮 |
| cannon 坦克炮/榴弹炮 | 弹药 | 6 / 2.2s | 105~220mm |
| shotgun 霰弹 | 弹药 | 6 / 2.2s | 鹿弹、独头弹、AA-12 |
| sniper 狙击/反器材 | 弹药 | 5 / 2.4s | M99、M82、NTW |
| launcher 火箭/导弹 | 弹药 | 10 / 2.6s | 陶式、短号、地狱火 |
| flamer 火焰 | 燃料 | 60 / 2.4s | 凝固汽油 |
| laser 激光 | **能量** | 无弹匣 | 线圈步枪、轨道炮 |
| melee 近战工程臂 | **能量** | 无弹匣 | 打桩机、液压剪、链锯 |

- 实弹：消耗**实体弹匣**（`MAG_ITEM` 把武器映射到 `mag_*` 物品）。打空后弹匣消失；装填完成时从货舱扣一个对应弹匣，货舱没有则空仓、无法开火。出发时装填同样各消耗一个。
- 激光：每发 `cost`（1.6）能量，无换弹。
- 近战：每击 0.3 能量，无换弹。
- 应急模式（能源耗尽）下所有武器停火。

### 2.2 DPS 公式

```
单发总伤害 = dmg × pellets（仅 shotgun 有多弹丸）
爆发 DPS   = 单发总伤害 × rate
持续 DPS   = 单发总伤害 × mag / (mag / rate + reload)
```

- 爆发 DPS 用于短窗口；持续 DPS 计入换弹。
- 实际命中还要乘以散布命中率；审计表是“理论满命中”。
- 激光/近战无换弹，持续 DPS = 爆发 DPS。

### 2.2.1 占空比与风险调整 DPS

射程是硬代价：3m 近战与 70m 机炮的理论 DPS 不可直接比较。审计表新增两列：

```
风险调整 DPS = 持续 DPS × (1 − 0.55 × (1 − ap)) × 占空比
```

| 类型 | 占空比 | 依据 |
|---|---:|---|
| 近战 | 0.30 | 必须贴到 3m，面对移动目标大部分时间在接近 |
| 霰弹 | 0.55 | 需进 16m，散布与走位 |
| 火焰 | 0.50 | 有效 9~15m |
| 机枪 | 0.70 | 中距离持续压制 |
| 自动炮 | 0.65 | 中远距离点射 |
| 坦克炮 | 0.55 | 装填与弹道 |
| 狙击 | 0.60 | 需停顿瞄准 |
| 火箭 | 0.55 | 装填与飞行 |
| 激光 | 0.70 | 无弹道、即时命中 |

当前结论：PB-09 理论有效 DPS 124.8，按 0.30 调整后为 37.4（第 16 名）；要与 GAU-8 的 66.2 等价，占空比需达到 **0.53**。近战在虫群、巢穴、被控制/背身 Boss 场景占空比会显著更高，属于**场景特化武器**，不是数值崩坏。审计表按单体移动目标给基准值，不要拿它给近战判死刑。

### 2.3 穿甲与护甲

```
穿甲系数 ap = clamp((pen − 15) / 62, 0.0, 0.85)
敌人常驻减伤 = clamp(armor × (1 − ap), 0, 0.9)
正面折射     = clamp(front_resist × (1 − ap × 0.65), 0, 0.9)
最终伤害     = 基础伤害 × (1 − 常驻减伤) × (1 − 正面折射) × 弱点倍率
```

- `pen` 14（霰弹鹿弹）→ ap 0；`pen` 28（基础机枪）→ 0.21；`pen` 52（自动炮）→ 0.60；`pen` 68+ → 0.85（封顶）。
- 敌人护甲分层：无甲 0；甲壳/重甲虫 0.25~0.45；Boss 0.25~0.55。
- 弱点：Boss 背部 `weak_back` 1.8~2.2，核心暴露 `weak_core` 2.5~3.0。

### 2.4 距离衰减（新）

```
飞行距离 d
近距阈值 near、远距阈值 far、最低倍率 min
伤害倍率 = 1.0                                  (d ≤ near)
         = lerp(1.0, min, (d−near)/(far−near))  (near < d < far)
         = min                                  (d ≥ far)
```

| 类型 | near | far | min |
|---|---:|---:|---:|
| 狙击 | 1.20×射程 | 3.20×射程 | 88% |
| 激光 | 1.00× | 2.60× | 82% |
| 火箭/导弹 | 0.80× | 2.60× | 78% |
| 坦克炮 | 0.80× | 2.60× | 70% |
| 自动炮 | 0.60× | 2.20× | 55% |
| 机枪 | 0.50× | 2.00× | 50% |
| 火焰 | 0.40× | 1.30× | 18% |
| 霰弹 | 0.35× | 1.00× | 10% |
| 近战 | — | — | 100%（3m 扇形内即时命中） |

- “射程”米数 = `reach_m`，或 `range × 3`（无 reach_m 时）。
- 近战不生成弹丸：以机体中心为圆心、`reach_m` 为半径、前方约 127° 扇形即时判定（打桩机 3m / 链锯 3.5m），扇形外与身后均不命中。
- 弹丸寿命 = `clamp(射程 / 速度 × 6, 2.5, 6.0)` 秒，不再在射程尽头消失。
- 弹丸从实际枪口指向准星；超过原射程仍能命中。

### 2.5 爆炸/AoE

```
raid.explode(位置, 半径, 伤害)：
  对半径 + 0.8m 内所有虫/巢/流浪者直接 take_damage(伤害)
```

- 当前实现：范围内固定伤害，不按距离衰减、不携带穿甲参数（`ap=0`）。
- projectile 的直击伤害已经过距离衰减；爆炸伤害取命中点衰减后的 `hit_dmg`。

## 3. 敌人

### 3.1 属性与攻击 DPS

```
攻击周期 = windup + strike + recover
攻击 DPS = dmg / 攻击周期
```

- 这是近战/单次攻击的粗略值；多段齐射、远程弹道、召唤、Boss 技能未计入。

### 3.2 护甲与正面

| 类别 | armor | front_resist |
|---|---:|---:|
| 无甲软目标（跳虫/酸液/镰爪/爆浆/啸翅/狙击虫） | 0 | 0 |
| 甲壳/重甲虫（晶背/机甲虫/铁颚/盾卫/巨像） | 0.25~0.45 | 晶背 0.55、盾卫 0.65、巨像 0.45 |
| Boss / 领主 | 0.25~0.55 | 棱镜 0.38 等 |

- 护甲与正面折射乘算：晶背正面总减伤可到 ~70%，绕后收益显著。
- `armor_pierce`（敌人攻击）只削玩家 `stats.armor`，不削 `armor_class` 加成。

### 3.3 TTK

```
单把武器对目标 TTK = 目标 HP / (持续 DPS × (1 − armor × (1 − ap)))
```

审计基准（单把、满命中、无弱点）：

| 目标 | HP | armor | 机枪 | GAU-8 | 120mm 炮 | 地狱火 |
|---|---:|---:|---:|---:|---:|---:|
| 深渊母皇 | 2800 | 0.55 | 88.7s | 27.5s | 61.6s | 38.4s |
| 裂谷铁甲王虫 | 1900 | 0.50 | 56.2s | 18.2s | 41.4s | 25.9s |
| 铁锈重甲王虫 | 1150 | 0.45 | 32.0s | 10.7s | 24.8s | 15.5s |
| 六足要塞 | 3600 | 0.48 | 103.8s | 34.1s | 78.1s | 48.9s |

- 双持、技能、弱点、队友会显著缩短。
- 基础机枪对终章 Boss 单把 88.7s，属于“需要换穿甲武器/组队”的设计区间。

## 4. 背部模块

| 模块 | 公式 | 当前值 |
|---|---|---|
| 导弹/火箭 | `齐射伤害 = dmg × count`；`轮均 DPS = 齐射伤害 / cd`；`能耗/秒 = cost / cd` | 火箭 224 / 8s = 28；导弹 192 / 7s = 27.4；VLS 504 / 13s = 38.8 |
| 护盾 | `覆盖率 = dur / cd`；激活时免疫伤害并修复各部位 35% 损伤 | 4s / 11s = 36% |
| 货舱 | `净增 = cargo − w` | 货架 18−5=13；货包 12−2=10 |

- 导弹每枚带 `homing`、`aoe=3.2`，爆炸走固定伤害（不穿甲）。
- 护盾激活瞬间修复部位，不回复总 HP。

## 5. 经济

```
商店买入价 = 物品价值 v × 1.25
玩家卖出价 = 物品价值 v
```

- 物品价值直接写在 `ITEMS`/`MODULES` 的 `v` 字段；模块价格梯度：r0 ~300-400、r1 ~700-1500、r2 ~1900-3000、r3 ~3200-4800、r4 ~5000-5400。
- 掉落分档：容器品质由所在区块的「military + safe 权重占比」决定（`GameData.zone_tier`）：
  ≥55% → 3 档、≥30% → 2 档、其余 1 档。`C` / `S` 区为 3 档，`D` / `I` 区为 2 档，野外为 1 档。
  档位不显示成等级标签，而是直接换箱子名字：

  | 箱型 | 1 档 | 2 档 | 3 档 |
  |---|---|---|---|
  | supply | 补给箱 | 军需补给箱 | 野战补给栈 |
  | tool | 工具箱 | 维修工具箱 | 工兵器材柜 |
  | military | 军用储物箱 | 军械箱 | 指挥所军械柜 |
  | safe | 保险柜 | 加固保险柜 | 加密保管柜 |

  | 档 | 出货件数 | @module 权重 | 模块稀有度 r0~r4 | military 单箱期望 |
  |---|---:|---:|---|---:|
  | 1 | +0 | ×1.0 | [2.5, 5, 2, 1.2, 0.15] | ¥1379 |
  | 2 | +0 | ×1.15 | [2, 5, 2.5, 1.4, 0.18] | ¥1597 |
  | 3 | +1 | ×1.40 | [1.5, 5, 4, 2.5, 0.35] | ¥3141 |

  单件概率（普通池已剔除 5 件初始装配，r0 实际只剩 3 件）：

  | 档 | r0 | r1 | r2 | r3 | r4 |
  |---|---:|---:|---:|---:|---:|
  | 1 | 7.7% | 5.1% | 0.51% | 0.26% | 0.23% |
  | 2 | 6.0% | 5.0% | 0.63% | 0.30% | 0.27% |
  | 3 | 3.8% | 4.2% | 0.83% | 0.45% | 0.44% |

  旧权重下「单件 r3（0.08%）比 r4（0.141%）更稀有」的倒挂已修掉。按每局 3 个军用箱估算：1 档抽到指定 r4 约 148 局、3 档约 37 局；凑齐 6 件 r4 分别约 888 / 223 局。

  区块总期望（含箱型分布与密度，以 `D` 区 = 100）：`C` 175 / `S` 106 / `D` 100 / `I` 79 / 其余 18~63。终章图因 `C` 区密集，整图货值约为旧版的 2 倍。

  搜刮耗时（每件）：`LOOT_TIER_TIME` = 1 档 0.55s / 2 档 1.00s / 3 档 2.00s，再乘 `ab_search` 专精系数（每级 −4%，下限 0.5）与底盘承重破拆系数 `clamp(1.60 − 0.70 × load/120, 0.90, 1.35)`。

  | 套装 | load | 3 档箱 4 件（专精 0 / 5） | 1 档箱 2 件 |
  |---|---:|---:|---:|
  | starter | 48 | 10.6s / 8.4s | 1.5s |
  | assault | 72 | 9.4s / 7.6s | 1.3s |
  | heavy | 92 | 8.5s / 6.8s | 1.2s |
  | siege | 140 | 7.2s / 5.8s | 1.0s |

  低装在 `C` 区开一个 4 件 3 档箱要站桩 10.6s，而该区虫群 DPS 普遍 18~25（裸装 4s 内致死），等于开不完——装备门槛由此成立。
- 委托：`REQUEST_POOL` 固定 `count / reward`，通常高于直接卖价。
- 弹药（实体弹匣，打空即消失；商店可买，补给箱/工具箱/军用箱可搜）：

  | 弹匣 | 价格 | 发数 | ¥/发 | 满射 ¥/秒 | 重量 |
  |---|---:|---:|---:|---:|---:|
  | 12.7mm 弹链箱 | 216 | 36 | 6 | 48 | 2.0 |
  | 30mm 机炮弹鼓 | 900 | 36 | 25 | 150 | 4.0 |
  | 120mm 炮弹架 | 1080 | 6 | 180 | 126 | 6.0 |
  | 霰弹弹匣 | 240 | 6 | 40 | 100 | 2.0 |
  | 反器材弹匣 | 1500 | 5 | 300 | 300 | 3.0 |
  | 导弹发射巢 | 5000 | 10 | 500 | 600 | 8.0 |
  | 凝固汽油罐 | 300 | 60 | 5 | 60 | 4.0 |

  机枪单局打 10 匣 = ¥2160，约占 12 容器期望收益（6105）的 35%；导弹流受 8kg/巢的重量限制，基本只能用于 Boss。初始配给 4 个机枪弹匣（出发装填消耗 2 个，余 2 个备用）。
- 物品按「重量定行数 + 2D 网格摆放」双约束（`GameData.pack_cargo_inplace` → `GridPack`），不是单纯按 kg 计价。

## 6. 成长

| 来源 | 叠加方式 | 满级量级 |
|---|---|---|
| 飞空艇设施 | 每级 `stat` 线性加算 | 结构 +25、护甲 +10%、耗能 −0.02、货舱 +5 等 |
| 研究节点 | 一次性 `stat` 加算 | 结构 +20、能源 +20、护甲 +2% 等 |
| 驾驶员等级 | `level_stat × (等级−1)` | 小量 |
| 船员好感 | 每级 `stat` 线性加算 | 小量 |
| 实战熟练度 | 每级 `stat` 线性加算，max 10 | 小量 |
| 出击餐点 | 每次行动的临时加成 | 能量/结构 |

- 所有成长都是加算，不改变模块基础值；相对 400+ 结构、30%+ 护甲的新模块，成长占比约 5%~10%。

## 8. 已发现的不合理点

> 先说明：价格倒挂、稀有度价格梯度、护盾文案与实现、高价值武器 DPS 单调性、背部货舱倒挂已在最近几轮校准，以下只列**当前仍然存在**的问题。

### 循环级（P0）

- **A. 装备升级没有收益杠杆**
  风险随装备线性上升，收益却不随装备上升。全损机制下（`main.gd` 出击即清空 `loadout` 并存档，失败不还原），套装价格：starter ¥1950 / assault ¥10250 / heavy ¥20000 / siege ¥22550；而 heavy 的货舱仍是 24，比 assault 的 38 还低。按单局 12 容器期望 ¥6105 计算，85% 撤离率时 heavy 期望 2189 < starter 4896，heavy 要追平 70% 撤离率的 starter 需要 **90.8%** 成功率。
  结果：理性最优永远是"最便宜套装刷"，高端装备沦为展示品。
  修复方向：高价值容器（safe / military）只在高危区或 Boss 房出现；稀有掉落权重随区域深度提升；重型底盘货舱 24→40，让"贵装备"同时是"高收益装备"。
  已做 4/4：容器按区块危险度分 3 档并附带搜刮耗时门槛（见 §5）；`core_fortress` 货舱 24→40（heavy），`legs_hex_colossus` 追加 8（siege 48）。重型套装现在既能站住 `C` 区，也能把 10~16kg 的模块多带回 1~2 件。按 13kg/件的模块估算，平衡成功率从 heavy 77% / siege 79% 降到 **65% / 67%**（assault 63% → 55%，starter 仍 24%），曲线回到「贵装备更划算但风险仍实」。

- **B. 审计口径缺占空比（已修）**
  旧审计只输出理论满命中 DPS，会把 3m 近战与 70m 机炮放在同一把尺子上比较。现已加入 `uptime` / `sustain_vs_boss` / `risk_adj_dps` / `v_per_risk_adj` 四个字段并改按风险调整 DPS 排序。按 0.30 占空比，PB-09 从第 1 名落到第 16 名（37.4），与 GAU-8（66.2）等价需占空比 0.53。

### 高优先级

1. **爆炸伤害不穿甲、不按半径衰减**
   `raid.explode` 对范围内目标固定 `take_damage(dmg)`，`ap=0`。炮/导弹/AoE 对 0.55 甲 Boss 只能吃基础伤害，边缘与中心同伤；与直击的穿甲收益不一致。建议给 `explode` 加 `ap` 与 `(1 − dist/radius)` 衰减。

2. **“射程”单位与衰减距离脱节**
   面板显示 `range`（10/14/22 抽象值），实际米数是 `reach_m` 或 `range×3`，而衰减 `near` 又是射程的 0.35~1.2 倍。玩家看到“射程 22”无法知道 74m 内满伤。建议 UI 显示米数并标注“满伤距离”。

3. **能源作为“行动时钟”已基本失效**
   实弹不耗能后，待机 18~50 分钟；只有激光/技能/冲刺耗能。搜打撤的“能源倒计时”设计目标不再成立。建议提高基础待机耗能，或让实弹供弹/伺服也消耗少量能源。

4. **护盾强度偏高**
   4s 无敌 / 11s 冷却 = 36% 覆盖，且瞬间修复 35% 部位损伤，价格仅 1600。对 Boss 战接近“每 11 秒 4 秒无敌”。建议降低覆盖率或把修复改成持续回复。

5. **~~霰弹与近战的距离定位被拉长~~（近战已修）**
   近战工程臂曾按 9~12m 弹丸飞行，现已改为机体中心 3~3.5m、约 127° 扇形即时判定，不再生成弹丸。霰弹超出 16m 仍有 10% 伤害且弹丸继续飞，仍待调整（可降到 5% 或让远端弹丸提前消散）。

### 中优先级

6. **穿甲溢出**：`ap` 在 `pen≥68` 全部封顶 0.85，pen 68/72/74/78 完全同效；6 级穿深内部没有梯度。
7. **玩家防弹等级不参与被穿甲**：敌人 `armor_pierce` 只削 `stats.armor`，`armor_class` 的 +3%/级 永远不被破甲，防弹等级收益固定。
8. **散布单位不一致**：面板 `spread` 5.5°，实际有效半角约 2.75°；玩家看到的数值不是有效角。
9. **持续射击无精度累积**：机枪/加特林没有 bloom/后坐扩散，理论 DPS 与实战命中率差距大；高射速武器在审计中偏强。
10. **追踪导弹的距离衰减按飞行路径**：`homing` 绕圈会增加 `flight_dist`，可能意外降低伤害。
11. **敌人攻击 DPS 口径过简**：`windup+strike+recover` 不含齐射、远程弹道、召唤与 Boss 技能；Boss 实际威胁被低估。
12. **经济通胀**：r3 模块价值 3200~4800，军用箱 45% 出模块，单次行动收益可能远超委托/商店；r4 权重 0.15 又让顶级模块极稀有，形成“要么暴富要么永远不出”的分布。
13. **高价武器 ¥/DPS 仍高**：120mm 炮 91 ¥/DPS，基础机枪 5.4；虽然单发/穿甲/射程有溢价，但面板性价比仍显得“越贵越弱”。

### 低优先级

14. HUD 能源剩余秒数不含开火消耗，激光持续射击时偏乐观。
15. 火焰弹丸寿命 6s × 16m/s = 96m，未覆盖 150m 地图（实际射程 9m，影响小）。
16. 敌方酸液 `spawn_spit` 仍是 1.4s 短寿命，不套用距离衰减。
17. 超载 >40% 直接触底 40%，非线性但可接受。
18. `hp` 只由躯干提供，腿/臂/背/炉不提供结构；部位损坏与总 HP 脱节。
19. `armor_class` 只取 max(躯干, 底盘)，不叠加，6 模块体系不对称。
20. 物品 `v/kg` 差异大（虫晶 1500/kg vs 食物 60/kg）。货舱实际是「重量定行数 + 2D 网格摆放」双约束（`GameData.pack_cargo_inplace` 调用 `GridPack`），并非单纯按 kg 计价；本文档早期写的「没有体积/占格」已过时。

21. （已修）同类型重复定位：密集阵、MK108、LAU-61、AA-12 曾「更贵且更弱」。现调整如下：
    - `arm_phalanx` pen 30→42、v 4650→4350（近防脱壳穿甲弹定位）
    - `arm_mk108` dmg 21→26、pen 36→38（短管高爆对软目标）
    - `arm_lau61` pen 40→46、v 3650→3150（廉价多管火箭巢）
    - `arm_aa12` pen 18→22、v 3000→2600（全自动霰弹）
    现仅剩近战 `arm_cs88` 略弱于 `arm_th60`（¥4350 vs 4100），按「暂不动近战」的约定保留。

22. （已修）容器出货概率没有差异：此前所有区块共用同一张掉落表。现由 `GameData.zone_tier(weights)` 按 `military + safe` 占比分 3 档，`roll_loot(table, rng, tier)` 调整出货件数、`@module` 权重与模块稀有度；`_place_box` 按落点所在区块自动取档，箱子按档位换名字（军用储物箱 → 军械箱 → 指挥所军械柜），不显示等级标签。

23. （已修）缺装备门槛：高档箱搜刮耗时按档位与底盘承重放大（`LOOT_TIER_TIME` + `mech.stats.load`，见 §5）。低装在 `C` 区开 4 件 3 档箱需 10.6s，虫群环境下实质不可完成；`siege` 为 7.2s（专精满 5.8s），重型套装由此在高危区获得正向收益。

24. （已修）重型套装货舱比中型更小：`heavy` 货舱曾只有 24（`assault` 38），形成「越贵越装不下」的倒挂。现 `core_fortress` cargo 24→40（heavy = 40），`legs_hex_colossus` 追加 cargo 8（siege = 48）。模块重 10~16kg，多带 1~2 件就是 3~8k 的收益差。

25. （已修）实弹弹药零成本：旧逻辑换弹直接 `ammo = mag`，不消耗任何资源。现改为 7 种实体弹匣物品，装填完成时从货舱扣一个、打空即消失，货舱没有则空仓且提示「没有可用的弹匣」；商店可买，补给箱/工具箱/军用箱可搜，初始配给 4 个机枪弹匣。

26. （已修）设定与命名冲突：旧 `gold` 是 `v=1200` 的硬通货，但本作硬通货是信用芯片（`credit_s` / `credit_l`），黄金没有流通价值。现改名「旧世界纪念金条」，`v` 1200→200，仅作收藏品；`safe` 第三档随之改名「加密保管柜」。`safe` 单箱期望 578→471（金条占 4/75 权重）。Boss 奖杯池与 5 张残骸掉落表里的 `gold` 权重已并入 `credit_l`（`boss_queen` / `titan` / `overlord` / `citadel` / `carrier`），Boss 收益不受影响。

27. （已修）模块池的三个问题一起修：
    ① Boss 掉落的高级筛选写错字段（`md.get("price")`，模块只有 `v`），导致 `high_mods` 永远为空、回退成「全部非初始模块均匀抽」；已改为 `v >= 650`。
    ② 稀有度权重按「单件概率」重配，修掉「单件 r3 比 r4 稀有」的倒挂（0.08% vs 0.141% → 0.26% vs 0.23%）；`@module` 权重 45→28 对冲通胀。
    ③ 普通池剔除 5 件初始装配（`core_scout` / `legs_biped` / `back_cargo` / `gen_cell` / `arm_mg`）。
    `military` 单箱期望 1120 / 1335 / 3114 → 1379 / 1597 / 3141（+23% / +20% / +1%），整体通胀约 20%。

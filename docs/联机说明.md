# 2–4 人合作联机

从机库右上角点击 **联机小队**。每位玩家先在自己的机库装好机甲和货舱，再进入房间准备。

1. 房主填写驾驶员名称、UDP 端口（默认 **27847**）和可选口令，点击创建房间。
2. 队员输入房主 IP 或域名、相同端口与口令，点击加入房间。房主界面会列出本机 IPv4 地址；有多个网卡时选择队员能访问的那个地址。
3. 房主选择战区，所有人点击准备，房主点击全员空投。至少两人、最多四人。
4. 返回整备会取消自己的准备；房主换地图、人员加入或退出会取消全员准备。出击前再次核对已准备的装备，避免旧配置被带入行动。

局域网使用内网地址。跨公网可用可达的公网地址并在路由器转发选定的 UDP 端口，也可使用虚拟局域网。Windows 防火墙需允许游戏通信。此实现没有匹配服务器、Steam 邀请或 NAT 中继，因此普通私网地址不能直接跨互联网连接。

## 行动规则

- 房主计算移动碰撞、武器弹药、伤害、敌人、战利品和撤离。客户端发送移动、瞄准与操作请求，接收权威状态并平滑显示角色。队员的设施、研究、驾驶员、船员、餐点与能力加成由房主按相同数据表计算。
- 合作玩家之间没有武器友伤。敌人与危险区域可攻击不同队员；已撤离机甲不再承受伤害或吸引敌人。AI 随行小队沿用房主的部署仓配置。
- 容器共享，每人货舱独立。搜索揭示、拿取、存入、整理、丢弃、战地换装和消耗品使用均经房主确认。容器版本及货舱校验阻止陈旧索引和重复领取；队友更新物品后可能需要重新选择。
- 每人可独立前往固定撤离点或运输机。撤离成功立即写入自己的存档；等待期间观战存活队友，所有人结束后显示结算。已成功撤离的收益不会被随后房主掉线覆盖。
- 队员损毁或弃机后其余人继续行动。房主的角色死亡也不会关闭服务。行动时打开暂停/设置只阻止本地操作，世界继续运行。
- 跨区需要所有仍在行动的玩家在同一个转场口集合两秒；共同加载新地图，保留各自生命、能源、部件、弹药、冷却、装备和货舱。用场景代次丢弃旧地图的迟到消息。
- 客户端断开视为弃机；房主断开结束当前会话。未成功撤离的装备和货舱按失败处理。可回机库重新建房/加入；**不支持在行动中加入、恢复已断开的机甲或迁移房主**。
- 游戏代码、数据和引擎版本必须一致；加载后还会校验地图占地与撤离点，全部完成才解除加载屏障。

出击及结算沿用本地存档。这是熟人合作协议，房主不能从外部验证队员本地存档中的物品所有权，也没有竞技反作弊服务。

## 实现与验证

- `scripts/net/session.gd`：ENet 连接、握手、房间、准备、加载屏障、输入和可靠操作、结果幂等、超时和断开。
- `scripts/net/coop_raid.gd`：每位玩家的角色与行动上下文、实体生命周期、权威事务、15 Hz 状态快照、30 Hz 操作输入、插值与战斗效果。
- `scripts/net/protocol.gd`：有界装备/成长数据、槽位与物品检查、有限数输入验证。网络不反序列化对象，也不允许远端指定脚本路径或调用任意方法。
- 快照压缩后拆为不超过 1000 字节的数据块，有限缓存重组；新快照自动覆盖丢失的旧快照。物品、生命终局、实体生成和危险预警使用可靠通道。
- `scripts/net/lobby.gd`：复用游戏现有像素主题的房间界面；游戏中显示队员状态、头顶名称、雷达标记和延迟。

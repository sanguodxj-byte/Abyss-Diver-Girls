# 长时性能监控与生命周期修复

后续进展：本报告中的反射探针泄漏已在单独构建的 Godot 4.7.2 修补运行时中通过 20 轮机库测试；旧官方运行时仍会复现。最新运行时、打包与性能证据见《修补运行时验收-2026-11-20.md》。下面保留前一轮采样和当时结论。

本轮针对持续战斗和反复出入战区，扩展了真实窗口监控；历史短测保留在《卡顿专项优化-2026-11-20.md》。场景和测试路线已经变化，不直接用两份报告的 FPS 差异推算优化幅度。

## 已复现与修复

| 问题 | 修复前证据 | 修复后定向回归 |
|---|---|---|
| 冲刺烟迹没有结束发射和释放节点 | 20 次冲刺后仍有 20 个持续发射节点 | 停止发射并等待最后一批消散后，残留 0 |
| 超额普通尸体只隐藏，仍保留节点和资源 | 创建 64 具后仍有 64 个对象，只有 18 个可见 | 对象数与既有 18 个可见上限一致；独立掉落箱不随尸体删除 |
| 无炮管虫跳过死亡收尾 | 收尾回调错误地位于 `if gun` 分支内 | 实际 ling 死亡后护盾释放、处理停止 |
| 静态爆发粒子池残留旧场景引用 | 三次父场景退出后留下 3 组键 | 父场景退出时清理，三次退出后为 0；相同效果仍复用原节点 |
| 自爆虫死亡引信跨退图访问已释放对象 | 点燃后立即退图触发 lambda capture freed 错误 | 引信由战区拥有；22 只同时死亡仍触发 22 次爆炸，退图后回调取消，回归通过 |
| 机库只有一个反射探针，却分配默认 64 槽图集 | 首轮机库引擎显存 1,028.46 MiB | 图集容量设为 4，分辨率不变，占用降至 562.91 MiB，减少 465.56 MiB |

`tests/effect_lifecycle.gd` 与 `tests/burst_lifecycle.gd` 负责上述回归。无界面粒子池测试以 `finished` 信号进入正式回池路径；真实窗口长测负责实际渲染下的自然结束行为。修改 `art.gd` 后重新烘焙了 69 个 NPC 模块，保持资源来源指纹一致。

反射图集变更经过四轮真实机库创建/释放、整备/交易/降落/仓库/图鉴导航，以及修改前后截图检查。单独的每轮 3 MiB / 7 个 Texture RID 泄漏已缩小到 Godot 4.7.2 反射探针颜色缓冲清理遗漏，尚未修复引擎；详见《Godot472反射探针资源问题.md》。没有移除正式反射探针、降反射分辨率或关闭环境效果。

## 监控方法

- 默认 1920×1080、quality=1、Forward+、关闭 VSync；保存实际窗口/渲染尺寸、MSAA、GPU 和渲染倍率。
- 固定种子、两名队友、三名排队增援，真实输入持续开火和移动。玩家获得测试用生命/能量保护；这不是难度或死亡流程验收。
- 每 10 秒落盘平均帧时间、P95/P99/最大帧、超过 33.3/45/100 ms 的帧数、最慢四帧、流水线编译计数、引擎内存、对象/节点/孤儿数、特效池与缓存数量。0.1 ms 分桶保存整局分位数上界，不无限保存逐帧字典。
- 系统侧每两秒采样进程工作集、私有内存与 CPU。游戏返回机库后验证旧战区实例已释放，并记录机库资源基线。
- 五分钟场景要求三次事件均选到实际落点，并检查持续开火次数；巡逻路线避开自动转场通道。单独的 `transit` 测试覆盖换图功能。
- 独立快照复制源码、资源和导入缓存；运行前后计算指纹。采样过程中其他 Godot 活动会使整轮时间数据无效，但保留功能/诊断记录。同项目可见预览按用户授权临时暂停，结束后恢复；其他无界面测试等待其结束。

两次铁锈工业带返回机库后：节点均为 1,288、孤儿均为 0、粒子池均为 0；静态内存为 356.84 / 357.94 MiB，差 1.09 MiB。缓存网格从 5,176 增到 5,347，仍有按变体增加的缓存，两个周期不足以证明无限长时间稳定。六图依次引入新纹理/网格，机库静态内存最终 407.96 MiB。

较早的 `ironbelt_fixed_v3` 完整五分钟为平均 116.0 FPS、P99 ≤17.9 ms、最大 80.610 ms，但第 170–260 秒有射击空窗，因此仅作为混合负载结果。测试现在每 0.5 秒重申按住输入，逐窗要求实际射击发生，避免窗口焦点/真实输入影响使持续交战空跑。

`review/monitor_regression.json` 记录 9 项通过：粒子池生命周期、烟迹/尸体生命周期、NPC 重烘焙、模块等价/指纹、九种普通敌人与 21 种首领、派系交战与掉落、跨区撤离、存档读写迁移、武器。完整结果在 `review/soak_summary.json`，来源及并发检查在各 `*_manifest.json`。

以下记录不作为性能验收：`baseline_long`、`lifecycle_long` 被并行 Godot 打断；`isolated_ironbelt` 等待其他测试超时，未开始采样；`ironbelt_cycle_baseline` 的旧巡逻路线触发正常换图；`ironbelt_fixed_v2` 未通过窗口尺寸检查。失败记录原样保留。

海湾区补充：`bayport_profile` 的 120 秒诊断运行遇到其他无界面 Godot 测试，时间不验收。它显示 NPC 死亡分支有约 8 ms 局部耗时，但不能据此解释整段帧率差异，未对该分支做猜测性改动。

`bayport_final` 在图集容量优化后完整运行 300 秒，三事件、实际落点、持续射击、返回机库均通过。原始统计平均 93.5 FPS、P99 ≤31.2 ms、最大 221.408 ms（含一帧 >100 ms），多段同时出现系统 CPU 98–100%，不视作干净的优化对比。原始 manifest 的并发告警经复核是自身子进程 PID 210176 在启动竞态中误报；进程树采样也记录它属于本轮。保留原 manifest，额外审计在 `review/soak_bayport_final_audit.json`，监控器已补父链验证。不能把原始 `valid=false` 隐去，也不能把所有剩余长帧断言为系统导致。

图集优化后机库五个导航页面真实渲染通过；最后一次引信调整通过 `corpse_blast_lifecycle` 与 `effect_lifecycle`，这些小范围后续变更没有用于反推既有六图 FPS。独立快照与当前源代码仍可能因地形任务继续工作而不同。

最后运行 `tools/test_coop.ps1 -Players 2 -Port 28859`，主机与客户端均以退出码 0 完成 `coop_smoke`：真实 ENet 双进程的移动、搜刮、生命状态、跨区和撤离结算通过。见 `review/monitor_coop.log` 和主客端日志。这是本地无界面联机回归，不包含公网延迟/断线、多设备渲染和四人长局。

监控器父链竞态修正后的 `monitor_race_check` 完成一次灰港加载、十秒采样及退图，`valid=true`、源码无变化、并发记录为空；仅验证采集工具，不作为新性能基准。`review/monitor_final_evidence.json` 汇总 13 项通过记录（包含烘焙与定向复测，非 13 个独立完整套件）及交付源码哈希。
